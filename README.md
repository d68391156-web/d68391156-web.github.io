## 运行与检查

需要 Node.js 22+、pnpm 10.18.3：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build
pnpm start
```

开发：`pnpm dev`。本地服务地址 `http://127.0.0.1:8768/`；`pnpm start`读取`out/`。双击`启动日本旅行规划.command`使用Python在8877端口打开静态成品。不要直接双击HTML。

## 现有用户如何切换

浏览器本地行程及报价不会自动覆盖。在“我的行程”点击“载入13天核心方案（东京5／大阪6晚）”；默认日期为2027-01-24，切换可撤销。旧酒店／机票查询条件独立保存，切换后请同步查询日期、复核报价并取消已过期的选择。同步机票默认羽田进、关西出、香港接驳，离境日为2/4；1/24凌晨抵达通常需兼查1/23起飞，起飞日期须手动按航班核对。

## 预算、住宿与报价边界

默认人民币10000元上限沿用原项目，金额是规划预留。日本住宿仅计算11晚，按默认每晚180元为1980元；返程可能需香港／深圳中转住宿，在“机场接驳及转机住宿”预留中另核。已有酒店报价只抵扣符合日本住宿夜晚的日期，重叠及覆盖返程夜的报价整条排除并提示。所有选择与报价仅表示预算参考，不代表预订成功。

国内接驳含长沙至出境地、香港经深圳回长沙；机票、行李、机场接驳及中转住宿分列。1/29新干线预留已在当天交通内，预算仅拆分，不重复相加。ROND餐饮、大室山等未知消费显示待核价，不把0当作免费；请保留门票／体验预留。购物集中2/2、2/3，默认购物预留300元可修改，不预先扣除预期退税。机票历史指示价不自动计入新行程。

凌晨抵达不保证凌晨入住，需寄存或另核前一晚房费。1/28伊豆单程约3小时以上，冬季强风停运和天黑时间需考虑。2/4回港后要提取行李、通关、过境深圳及转站，春运车票待预订；不保证现有衔接可实现最迟2/5到长沙。

酒店查价保留Trip.com、Agoda、Booking.com入口、条件复制、手动含税整单报价及分摊。平台是否接受日期参数须在搜索栏复核；本站无实时航班、酒店库存或订单接口。浏览器本地数据不跨设备同步，可使用JSON备份和行程分享。

## 数据与维护文件

- `data/core-trip.ts`：13天核心行程、住宿、交通规划及提示。
- `data/japan-spots.json`、`data/additional-spots.json`：原景点与新地点、坐标、官方入口及授权图片。全部89个地点采用各自不同的实景／产品参考照片，按文件路径与SHA-256双重检查不重复，来源和授权见`public/images/credits.json`及`/images/credits.html`。图片拍摄季节、年份不保证与本次旅行相同。
- `lib/hotels.ts`：住宿日期、建议段及11晚预算抵扣。
- `components/TripGenerator.tsx`：载入核心方案与天气换日；通用生成器不等同指定核心行程，使用时按实际住宿另核。
- `components/FlightSearchPanel.tsx`：羽田进、关西2/4出、香港接驳查询。
- `data/transport.ts`：当前路线交通比较；票价仅为预留。
- `components/ShoppingGuide.tsx`：购物日期、预算与原退税工具。
- `docs/ITINERARY-2027-UPDATE.md`：本次核对来源与限制。
- `QA.md`：检查结果与验证范围。

## GitHub Pages

保留原仓库及Pages地址。`.github/workflows/pages.yml`安装依赖、运行测试／类型检查／Next.js构建，上传`out/`并发布；PR只检查，main推送或手动触发可发布。`next.config.ts`保持`output: "export"`，不需要后端或地图密钥。

远端原来只存源码ZIP和静态覆盖包。工作流兼容根目录源码，若根目录没有`package.json`则先解压当前`japan-travel-source.zip`，再执行同样的源码检查及构建；不再叠加旧`currency-update.b64`或原静态包。旧包保留供历史回滚，不参与新部署。GitHub Pages来源须为GitHub Actions。

回滚使用GitHub恢复上一提交及其工作流，或重新部署之前成功版本；浏览器本地数据仍保持原样。既有研究与恢复历史见`docs/RECOVERY.md`、`docs/UPGRADE-2027.md`及其他历史文档，旧日期不代表当前核心方案。
